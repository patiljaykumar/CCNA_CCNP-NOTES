## **OSPF(Open Shortest Path First) *P-89 |* L3**

- Algo- **Dijkstra's Shortest Path First |** **AD**\- ==**110**== (intra, inter, external area routes) | Link State Routing protocol (adv state of link to adjacent routers, Same LSDB(Ro) in same area)
    
- **Multicast groups**
    
    - IPv4-==**224.0.0.5**== MAC-==0100.5E00.0005== = Before Election- sentby- **Everyone-Hello packet exchange-** when ospf enabled on int | After Election- sent by- **DR to All OSPF Routers** | DR floods Type1, Type2 LSAs to all (BDR & DROTHERs)
        
    - IPv4-==**224.0.0.6**== MAC-==0100.5E00.0006== = sent-by- **DROTHER to DR & BDR** | DROTHER routers send LSAs(Type1) to DR & BDR describing its links
        
- after enabling OSPF
    
- **Metric**\- **Cost** (Bandwidth high = Cost low = prefered) | <span style="color: black;">No Hop Count Limit</span>
    
    - <ins>**Cost = Reference Bw/Int Bw**</ins> (Ref Bw= 100Mbps)
        
        - 10 Gbps, 1Gbps, 100 Mbps = 1 cost
            
        - 10 Mbps = 10 cost
            
- <ins>Updates</ins>\- **Triggered updates** known as **LSAs** (Link State Advertisements). If no change in topology LSAs refreshed every ==30min==. LSAs only include change not complete RT. LSAs stored in Ro **LSDB**(Link state Database) LSA- packets with info(Ro int, neigh Ro, net links) of state & conn of each Ro. allow Ro build sync view of net, cal shortest path, maintain RT
    
- can run multiple OSPF intances/processes on router, each will be isolated (maintain separate LSDB & RT) identified by **Process-ID** (range 1-65535) \[pid not have to be same on all Ro, pid are local to Ro\]

## Area

- OSPF divides AS into smaller parts called <ins>**Area**</ins> (for faster convergence). All Ro in area have same LSDB & complete map of net (know how to reach entire AS). 2 tier hierarchy
    
    - Area membership is set at <ins>int level</ins> (area-ID included in Hello packet) \[1 Router can can have multiple areas\]
- **<ins>DisAdv of using single Area</ins>** (if links & routers increases in area)
    
    - All Routers in area takes part in SPT(shortest-path tree) calc (eg- if link flaps)
    - Unmanageable if LSDB size increases. LSDB causes CPU & Memory overhead
    - No summarization of route info
- <ins>**Adv of using multiple Areas**</ins>\- Segmenting OSPF domain into multiple areas- 1)reduces size of LSDB(for each area), 2)making SPT calculations faster(limit CPU & mem use),  3)limits LSDB flooding when a link flaps to area
    
- Internal topology of 1 area is invisible from outside that area. 2 areas will not comm(exchange routes) with each other unless conn with Area-0 physically/virtually
    
- <ins>**Preventing Loops**</ins>\- All areas inject routing info into ***Area-0(backbone)***. Area-0 adv routes into other non-backbone areas.
    
- **Area-ID(32bit)**\- can be decimal(0-4.3billion) or dotted decimal(0.0.0.0-255.255.255.255). OSPD adv area-id in OSPF packets. Can form adjacency if decimal format used on 1 Ro & dotted on other Ro
    
- **ABRs(Area Border Routers)**\- Router with int in multiple areas & at least1 int in Area-0. ABRs adv routes from 1 area & inject them into diff area. ABRs compute SPT for every area they participate

## OSPF Packet Types- to exchange routing info

1.  **Hello-** sent periodically(all OSPF int) to discover neighbors, bring neigh relationship to 2-way state & monitor neigh continuous liveliness
    
    - | Data Field | Description |
        | --- | --- |
        | Router ID (RID) | unique 32-bit ID within an OSPF domain. |
        | Authentication Options | allows secure comm btw OSPF routers. Options are none, plaintext, MD5 |
        | Area ID | OSPF area OSPF int belongs to. 32-bit |
        | Interface Address Mask | net mask for primary IP for int out which hello is sent. |
        | Interface Priority | router int priority for DR elections. |
        | Hello Interval (==10s==) | time(s) router sends out hello packets on int `ip ospf hello-interval <1-65535>` |
        | Dead Interval (default-4xhello) | time(s) router waits to hear hello from neigh router before declaring it down.`ip ospf dead-interval <1-65535>` |
        | Designated Router, Backup Designated Router | IP of DR, BDR for that network link. |
        | Active Neighbor | IPs of OSPF neigh seen on that network segment (int) |
        
2.  **DBD/DDP(Database Description)-** used to exchange LSA headers during initial topology exchange(when adjacency first formed) \[so Ro knows list of neigh LSAs including their version\]
    
3.  **LSR(Link-State Request)-** router request part of neigh LSDB when Ro thinks its LSDB is outdated(if new DBD, LSA version found)
    
4.  **LSU(Link-State Update)-** explicit LSA for a specific network link, normally sent in direct response to LSR.
    
5.  **Link-state Acknowledgment-** sent to confirm receipt of LSU/flooding of LSAs (reliability)
    

* * *

**<ins>Neighbors</ins>\-** router that share common OSPF-enabled net link. Ro discover other neigh through Hello msgs. Each process maintains table for adjacent neigh & state of each Ro. **`debug ip ospf adj`**\- see neighborship state

- | State | Description |
    | --- | --- |
    | 1)Down | initial state of neighbor relationship. indicates router has not received any OSPF hello packets. |
    | 2)Attempt | ==state is relevant to NB (NBMA, P2M-NB) net type only== & require explicit(manual) neigh config. indicates that no recent info is received, but Ro is still attempting comm |
    | 3)Init | hello packet is received from another Ro (but no bidirectional comm) |
    | 4)2-Way | bidirectional comm established. If DR/BDR is needed, election occurs during this state. (all net not have DR/BDR) |
    | 5)ExStart | first state in forming adjacency. Ro identify Master/slave(election- master starts exchange) by DBD for LSDB synch (MTU match) |
    | 6)Exchange | Ro are exchanging link states by using DBD packets(actual LSDB info exchange) |
    | 7)Loading | LSR packets are sent to neigh, asking for more recent LSAs that have been discovered (but not received) in Exchange state. |
    | 8)Full | state in which neighboring routers are fully adjacent. |

## DR(Designated Router) & BDR(Backup Designated Router)

- DR & BDR used in OSPF to reduce no. of full mesh adjacencies. This reduces flooding of LSAs
    
    - no. of full mesh Adjacencies formed= ==**n(n-1)/2**== (n= no. of routers) \[Full mesh adjacencies increase= LSA flooding increase\]
    - 0<img src="../../_resources/dc302c4aaccf42510bf137f740734191.png" alt="dc302c4aaccf42510bf137f740734191.png" width="227" height="182" class="jop-noMdConv">
        - Reason- If change in R1 sends update to all Ro. R2 sends to all except R1. R3 sends to all except sender. similarly R4, R5. (this is excessive LSA flooding- CPU, Bandwidth overhead)
        - R5=DR, R4=BDR, R1=R2=R3=DROTHER
        - **Adjacencies**\- DR-BDR=Full | DR/BDR-DROTHER=Full | DROTHER-DROTHER=2-way (just hello msgs exchange no LSDB exchange, DROTHER able to send info to DR/BDR)
        - After DR/BDR election. DROTHER(R1) sends update to only DR(R5) & BDR(R4)\[224.0.0.6\]. Then DR adv it to all\[224.0.0.5\] {but SW sends multicast msg as broadcast}
- ### DR election criteria
    
    1.  highest OSPF priority(default=1) `ip ospf priority <value>`
    2.  highest RID (if same RID no neigh at all)
- **BDR election criteria**
    
    1.  2nd highest priority
    2.  2nd highest RID
- ==OSPF priority range 0-255. Default priority=1. If Priority=0 manually, that router not take part in DR/BDR election (Ro will be DROTHER)==
    
- ==Once DR/BDR elected & new Ro joins/ old Ro priority changed to highest, they will not become DR until OSPF process restarts on current DR (exception priority=0 manually changes to DROTHER)==
    
- ==As long as DR is up, BDR not advertises DROTHER updates to net, it just updates its local LSDB==
    
- ==If DR is down, BDR takes over role & new BDR is elected==

## OSPF Authentication

- **Null-** default auth. no password configured
- **Simple Password/ Clear text-**  password travels in clear text. prone to sniffing & MITM
    - global- `router ospf <process-id>`, `area <area-id> authentication`\- need to go to int further
    - or int- `int <int>`, `ip ospf authentication`, `ip ospf authentication-key <pass>`
- **MD5-** password converted into hash value
    - global- `router ospf <process-id>`, `area <area-id> authentication message-digest`
    - or int- `int <int>`, `ip ospf authentication message-digest`, `ip ospf message-digest-key <key-id> md5 <pass>`
- **HMAC-SHA-** pass converted into hash using HMAC-SHA algo. secure than MD5
    - `key chain <KC_name>`
    - `key <key-id>`
    - `key-string <pass>`
    - `cryptographic-algorithm hmac-sha-512` (diff versions here- 384, 256,1)
    - `int <int>`
    - `ip ospf authentication key-chain <KC_name>`
- ***Authentication on Virtual Links***
    - `area <area-id> virtual-link <router-id> authentication null`
        
    - `area <area-id> virtual-link <router-id> authentication authentication-key <key-value>`
        
    - `area <area-id> virtual-link <router-id> authentication message-digest message-digest-key <key-num> md5 <key-value>`

## Stub Areas Types

- Enterprise typically use default routes in 2 cases
    
    - To direct remote-site routers(branch, small locations) at edge of enterprise net to send all packets toward core(HQ) of enterprise (core routers know specific routes to dest)
    - To direct Internet-dest traffic of all enterprise routers towards Internet-connected router
    - To drive traffic inside an area toward ABR (default route to forward packets to ABR)
- Stub router provides simple way to enable function of flooding default routes inside area, driving IP packet back toward ABRs in that area. ABR in Stub areas advertise a default route in stub area. ABR chooses to not advertise inter-area routes (Type 3 LSAs), external routes (Type 5 LSAs) into the area. All routers in stub area can still route to dest (based on default route info) an routers require less mem & CPU
    
- ==Stubby areas use reason- reduce CPU time & memory consumption on routers (fewer LSAs in their LSDBs- using default routes to forward packets to ABR==)
    
- ==Backbone Area (Area 0) cannot be config as stub==
    
- <ins>Summary</ins>
    
    - ABRs create default route, using Type 3 LSA, listing subnet & mask- 0.0.0.0 & flood that into stub area. ABRs might not flood Type 3 LSAs into area
        
    - ABRs not flood Type 5 LSAs into stub area. (Routers inside stub areas cannot redistribute external routes into stubby area)
        
    - All routers in area must be config to stubby, else no neighborship
        
    - Default route has metric of 1 (unless `area <area-num> default-cost <cost>`)
        
- | Area Type | ABRs Flood Type 4 & 5 External LSAs into the Area? | ABRs Flood Type 3 Summary LSAs into the Area? | Allows Redistribution of External LSAs into the Stubby Area? | Default Route automatically originated? |
    | --- | --- | --- | --- | --- |
    | Stub | No  | Yes | No  | Yes |
    | Totally stubby | No  | No  | No  | Yes |
    | NSSA | No  | Yes | Yes (Type 7 LSA) | No  |
    | Totally NSSA | No  | No  | Yes (Type 7 LSA) | Yes |
    

1.  **Stub-** on all routers- `router ospf <process-id>`, `area <area-id> stub`
2.  **Total Stub**
    - ABR- `router ospf <process-id>`, `area <area-id> stub no-summary`
    - Other Routers- `router ospf <process-id>`, `area <area-id> stub`
3.  **NSSA (Not So Stubby Area)**
    - ABR- `router ospf <process-id>`, `area <area-id> nssa default-information-originate`
    - Other Routers- `router ospf <process-id>`, `area <area-id> nssa`

    - ABR- `router ospf <process-id>`, `area <area-id> nssa no-summary`
    - Other Routers- `router ospf <process-id>`, `area <area-id> nssa`

## Summarization

- Summarization is used to advertise multiple contiguous networks as a single route
- Advantages
    - Reduces size of RT & LSDB
    - Less Memory, Bandwidth, CPU overhead
    - Route flaps does not affect neigh
- In OSPF summarization can be performed on ABR/ ASBR only
    - ABR- `router ospf <process-id>`, `area <area-id> range <summarized-net> <summary-mask>` (area-id- source area from where routes originated)
    - ASBR- `router ospf <process-id>`, `summary-address <summarized-net> <summ`

## Route Filtering

- OSPF allows route filtering of Type3(on ABR only) & Type5(on ASBR only) LSAs
- **Filtering Type3 LSA**
    - Filtered on ABR only
    - can be filtered in inbound/ outbound dir
    - only Prefix-list is allowed (Access-list, Route map- not allowed)
    - ABR config
        - `ip prefix-list <PL_name> deny <net>/<CIDR>`
            
        - `ip prefix-list <PL_name> permit 0.0.0.0/0 le 32`
            
        - `router ospf <process-id>`
            
        - `area <area-id> filter-list prefix <PL name> <in/out>`
            
            - if filtering=inbound, area-id=dest-area | if filtering=outbound, area-id=src-area
- **Filtering Type5 LSA**
    - Filtered on ASBR only
        
    - can be filtered in outbound dir only
        
    - 2 ways
        
        1.  <ins>Redistribute connected command</ins>\- only route-map is allowed
            - `access-list <ACL_no.> permit <net> <wild>`
            - `route-map <RMAP_name> deny <seq-no>`\- not adv this net
            - `match ip address <ACL_no>`
            - `route-map <RMAP_name> permit <higher-seq-no>`
            - `router ospf <process-id>`
            - `redistribute connected route-map <RMAP_name>`
        2.  <ins>Distribute-list command</ins>\- ACL, prefix-list, route-map allowed
            - `access-list <ACL_no> deny <net> <wild>`
            - `access-list <ACL_no> permit any`
            - `router ospf <process-id>`
            - `distribute-list <ACL_no> out`

- ### Benefits of OSPF over EIGRP
    
    - **Open Standard**\- works with multi-vendor networks (EIGRP adv features depends on soft ver, licensing policies)
    - **OSPF Better scalability- EIGRP has no hierarchical, area-based design**
        - EIGRP- When route fails in large net- higher queries- high CPU use, convergence delays
        - EIGRP- Route summarization is manual (automatic summarization summarizes to classful boundaries) **OSPF supports it at area boundaries**
    - **Efficient Resource use**\- OSPF areas limits- LSDB size, Flooding of LSAs, CPU & mem use
    - **Structured control-** ospf  allows designers to:-
        - Control route flooding using **areas**
            
        - Control path selection using **simple cost metric**
            
        - Understand routing clearly using **LSDB**
